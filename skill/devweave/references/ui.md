# Interface

Ativar camada UI UX somente para experiência visível.

Converter direção visual em critérios:

- navegação por teclado;
- foco visível;
- contraste WCAG AA;
- labels e semântica;
- loading, empty, error e success;
- responsividade nos breakpoints relevantes;
- redução de movimento;
- estados hover, focus, active e disabled;
- conteúdo e hierarquia claros.

Reutilizar design system existente. Não deixar camada UI decidir arquitetura de backend.

## Fluxo visual

1. Ler brief, marca, usuário, conteúdo, plataforma e restrições.
2. Fazer pesquisa direcionada. Mobbin serve para fluxos reais; Dribbble e Pinterest para direção visual. Não copiar tela, marca, template pago ou identidade protegida.
3. Escolher macroestrutura e linguagem visual antes de componentes.
4. Usar Hallmark para criar, auditar, redesenhar ou estudar referência. Rodar gate anti-padrões e autocrítica antes da entrega.
5. Usar v0, Google Stitch, Subframe ou Antigravity para exploração e protótipo quando disponíveis. Tratar saída como rascunho sujeito a revisão.
6. Usar Aceternity UI e 21st.dev como fontes de componentes. Verificar licença, dependências, acessibilidade, desempenho e adequação ao design system.
7. Implementar menor solução coerente. Evitar gradiente decorativo, glassmorphism, cards repetidos, hero genérico, excesso de rounded corners e animação sem função quando brief não pedir.
8. Validar estados, breakpoints, teclado, leitor de tela, contraste, movimento reduzido, conteúdo real e regressão visual.

## Evidência

Para interface normal ou complexa, ligar critérios a screenshots nos breakpoints relevantes, testes de interação, auditoria de acessibilidade e punch list Hallmark resolvida ou aceita com justificativa.
